## The trap

The secret is the only credential an agent has, and this task is the one place in the product
that has it in hand after creation. Any path that carries it beyond the single response that
created it leaks it: a redirect with the secret in the query string, a diagnostics "test" button
that posts it back to the server, a snippet persisted in the page's RSC payload on a later
navigation, browser storage, or a log line from the server action. Every one of these passes a
happy-path test. The consequence is a live credential in browser history, proxy logs, or our own
logs, which D-009 forbids. That is why diagnostics read what the agent's own `connect_agent`
recorded and never use the secret.

Second trap: two routes here call `notFound()` (diagnostics with a foreign id, briefing with a
foreign slug). A `loading.tsx` above them turns the 404 into a 200 (board hazard 1e6662e8). Add no
loading boundary in `connect/` or `projects/[slug]/briefing/`.

Third trap: e2e tests from T08–T10 locate nav links by accessible name. A new nav label that
contains an existing one (for example "Agents") can break their strict locators. Run the full e2e
suite, not only yours.

  - `setupAgentConnection`: creates agent, token and defaults; reuses an existing agent whose name
    differs only in case; a restricted token with a default outside its projects gives
    `validation_failed` and creates nothing (count tokens, agents and defaults before and after); a
    project id from another org gives `forbidden_or_not_found` and creates nothing; agent caller
    gets `capability_denied`; audit rows exist and contain no secret or hash.
  - `getConnectionDiagnostics`: empty before connection; after `connectAgent` with that token the
    session appears; a session of the same agent under a different token does not; defaults outside
    a restricted token's projects are excluded; an archived project is read-only; an agent id or
    token id from another org gives `forbidden_or_not_found`, the same as a random uuid.
- **Unit:** the snippet generator for all four clients: contains the configured MCP URL, never a
  string matching `amb_[0-9A-Za-z]{8}_`, and the instruction block equals `AGENT_INSTRUCTIONS`.
- **e2e** (production server, as the existing specs do): owner runs the wizard; the secret appears
  once and is absent after reload, absent from every URL visited, and absent from the server log
  of the run. An SDK MCP client (as tests/e2e/mcp/sdk.spec.ts does) uses that secret and agent name
  to call `connect_agent`; refreshing diagnostics then shows the session, its projects and
  defaults. Owner B opening owner A's diagnostics URL and briefing URL gets 404. The briefing page
