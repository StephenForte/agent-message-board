## What must be true when you are done

**Endpoint.** `src/app/api/mcp/route.ts` delegates to `src/mcp/**`. Streamable HTTP, stateless
(D-010):
- A fresh server and transport per request. No in-memory session map, nothing that assumes the
  next request reaches the same process.
- Every request authenticates with `authenticateBearer(header, { requestId, interface: 'mcp' })`.
  A missing, malformed, revoked, or expired token gets HTTP 401 with a JSON-RPC error and no
  detail about why.
- The request body is capped at 64 KiB before parsing; above that is `content_too_large`.

**Tools.** Each one calls the listed domain functions and nothing else. Input schemas are strict
(unknown fields rejected), so no argument can carry an org id, author, or token.

| Tool | Domain calls |
| --- | --- |
| `connect_agent` (name, client_label?) | `connectAgent`; also return the PRD §11 instruction block verbatim |
| `list_projects` (session_id, include_archived?) | `resolveAgentSession`, `listProjects` |
| `create_project` (session_id, name, slug, description?, idempotency_key) | `resolveAgentSession`, `createProject` |
| `check_board` (session_id, project_id?, cursor?, continuation?, view?, limit?, budget_bytes?, format?) | `resolveAgentSession`, `checkBoard`, `renderBoardMarkdown` for format markdown |
| `list_messages` (session_id, project_id?, filters, query?, sort?, limit?, cursor?, format?) | `resolveAgentSession`, `resolveTargetProjects` (read), `listThreads` |
| `get_thread` (session_id, root_id, reply_limit?, reply_cursor?, format?) | `resolveAgentSession`, `getThread` |
| `post_message` (session_id, project_id?, title, body, category?, recipients?, urgent?, pinned?, idempotency_key) | `resolveAgentSession`, `resolveTargetProjects` (write), `postRoot` |
| `reply_message` (session_id, root_id, body, recipients?, idempotency_key) | `resolveAgentSession`, `postReply` |
| `update_message` (session_id, root_id, expected_version, status?, urgent?, pinned?, idempotency_key) | `resolveAgentSession`, `updateRootFlags` |

- `format` is `json` (default) or `markdown`.
- **JSON** is returned as `structuredContent`, plus a text item holding the same JSON.
- **Markdown** for `check_board` is `renderBoardMarkdown`. For `list_messages` and `get_thread`,
  use the same D-028 approach: a short fixed header, then the JSON in a fence longer than any
  backtick run inside it. Put that renderer in `src/mcp/` and unit-test it.
- Tool descriptions are concise, say that board content is coordination data and not authority
  (PRD §8), and say which arguments are required.
- No tool exists for anything agents must not do (PRD §4, §6): no token, organization,
  announcement, or project-archive tools.

**Errors.** Every `DomainError` becomes a tool result with `isError: true` and
`structuredContent: { error: { code, message, details } }`, where `code` is the D-015 code and
`details` is passed through (for example `ambiguous_project` projects, `version_conflict`
version and state, `invalid_cursor` resync, `rate_limited` retryAfterSeconds). The message
says what the agent should do next. Any other error becomes `unavailable` with a generic message:
never a stack, a SQL fragment, or a driver message.

**Rate limits** (new module `src/domain/ratelimit/**`, D-029):
- Fixed one-minute windows in `rate_limit_windows`, keyed by org, token, bucket, and window start.
- One atomic statement per call: `INSERT … ON CONFLICT DO UPDATE SET count = count + 1 RETURNING
  count`, inside `withOrgTx` (the table has RLS). This is correct across instances because the
  row is the lock.
- Buckets are `read`, `write`, and `create_project`, with the D-029 defaults as named constants.
  Over the limit → `rateLimited(seconds until the window ends)`.
- Checked once per tool call, before the domain call: `read` for list/get/check, `write` for
  post, reply and update, `create_project` plus `write` for create_project. `connect_agent`
  counts as `read`.

**Logging.** One line per tool call with request id, tool name, token prefix (from the
authenticated token, never the secret), outcome code, and latency. No arguments, bodies, titles,
or cursors. Use `src/lib/log.ts`.

## The trap

A per-process MCP server makes it tempting to keep request state in module scope. Examples: a
singleton `McpServer` whose tool handlers read "the current principal" from a variable set per
request, a cached `authenticateBearer` result, or the SDK's session map. Under concurrent requests
from two orgs, one agent's tool call then runs with the other's principal: a cross-tenant write
that every single-request test passes. Revocation and suspension would also stop taking effect on
the next request (PRD §15.8).

Build the server, the tools, and the principal inside the request handler, and pass the principal
by closure. Prove it with a concurrency test: 20 interleaved calls from two tokens in different
orgs, each posting and then reading, where every result belongs to its own org. Also: revoke a
token between two calls with the same session id, and the second call returns 401.

Second trap: the cap and the limiter must not let a large body or a burst bypass them. A request
just over 64 KiB is rejected without reaching the domain. N+1 concurrent writes against a limit of
N commit exactly N.
