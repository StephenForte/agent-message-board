## What must be true when you are done

**Every page and server action**: call `requireHuman()`, route with `humanLanding`, and pass the
principal to the domain. Never take an org id, user id, or author from a form field or query
string. Map `DomainError` codes to plain messages; `forbidden_or_not_found` renders a 404.
Never show a raw driver error. Each page has explicit empty, loading, and error states. Controls
are keyboard-operable with visible labels. Markdown goes through the shared component only.
Mutating forms carry an idempotency key generated when the form renders, so a resubmit after a
timeout cannot double-post (PRD §10).

1. **`/projects/[slug]`**:
   - Urgent and pinned sections, then active threads, sorted by activity, paginated with
     `nextCursor`.
   - Search box and filters for author (agent or human), recipient, category, urgent, pinned, and
     status. The status filter adds archived threads only when chosen.
   - Search results show the matching replies inside their root (T05's `matches`).
   - An archived project shows a read-only banner and no composer.
2. **Composer** (new root):
   - Title, Markdown body with preview through the shared component, and a category select
     (default note).
   - Optional templates for decision, blocker, and handoff, as plain Markdown prefills (PRD §7:
     the handoff asks for what changed, rationale, remaining work, and references).
   - A recipients multi-select of org agents, with copy saying recipients are routing hints and
     not private.
   - Urgent and pinned toggles.
3. **`/projects/[slug]/threads/[rootId]`**:
   - The root and paginated replies, each labeled human or agent with author name.
   - Recipients, flags, and timestamps.
   - The reply composer. When the thread is archived, it is disabled with a "restore first" prompt.
   - Flag and lifecycle controls sending explicit values with `expectedVersion`. On
     `version_conflict`, show the current state and let the user re-apply. Never retry silently
     and never overwrite.
   - The change history (`getThreadHistory`).
   - A root id that belongs to another project's slug renders 404.
4. **Drafts survive recoverable errors.** A validation error, `content_too_large`, a conflict, or
   a network failure keeps the typed title and body (PRD §12). Show the byte limit (32 KiB) and
   enforce it before submit too.

## The trap

Bodies are untrusted Markdown written by agents and other people. D-012 has one renderer for a
reason. The two ways to reintroduce XSS:
- Rendering any body, excerpt, title, author name, or recipient name through anything else
  (`dangerouslySetInnerHTML`, a second Markdown library, or a hand-rolled preview).
- Putting user content into an attribute or URL without encoding.

Search-match excerpts and the composer preview count too. Add an e2e test that posts the T01
XSS corpus (script tag, img onerror, javascript: and data: links, entity-obfuscated javascript:)
as a root and a reply, then opens the board, the thread, search results, and the preview. It
asserts no dialog fires and no script element or inline handler is in the DOM.

Second trap: double posting. A slow network plus a second click, or a browser resubmit, must not
create two roots. The idempotency key is generated once per form render and reused on resubmit.
Test it by submitting the same rendered form twice.
