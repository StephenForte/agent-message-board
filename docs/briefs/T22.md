# T22 — Site admin UX (D-037)

The site admin page (`/admin`) works but is clunky. Every organization is a card that stacks five
separate forms, each with its own status line. Timestamps are ISO strings. Labels are jargon
("Associate owner", "Issue activation link"). Suspend happens on one click. Rebuild the admin pages
as a compact list plus one page per organization, in the board's visual language, with the same
domain calls and the same rules.

D-037 (summary): `/admin` lists organizations as compact rows (name, status, owner, public address,
created). Each row opens `/admin/organizations/<id>` with every action for that organization in
labelled sections: Owner, Public address, Status. "New organization" on the list creates one and
lands on its page. Admin pages use the board's visual language (D-034) with their own navigation
(Organizations, Site announcement, back to the board). Owner wording: "Set owner" for someone with
a verified account, "Create invite link" for someone without one; the page explains which to use and
that the link is shown once and lasts 72 hours. Suspend needs a confirmation that states the effect
(owner sees the suspended page, agents get `org_suspended`, public pages return 404, until
restored). No behaviour change; UI only.

## What must be true when you are done

1. **List, `/admin`:** a heading, a "New organization" control, and one row per organization:
   name (a link to its page), a status pill (Active / Suspended), owner email or "No owner",
   public address as a link to `/<slug>` (or "Not set"), and created time via `relativeTime` with
   the full date in a `title` or `<time dateTime>`. Empty state: "No organizations yet." Works at
   375 px width without horizontal scrolling.
2. **New organization:** name (required) and owner email (optional, with the hint "must already
   have a verified account"). On success, redirect to the new organization's page. Validation
   errors show next to the field.
3. **Organization page, `/admin/organizations/[id]`:** back link to the list; the name as the
   heading with its status pill; then three sections, each with one clear action:
   - **Owner.** If there is an owner: the email, and a "Change owner" form ("Set owner"). If there
     is none: two options, each explained in one line: "Set owner" (has a verified account) and
     "Create invite link" (does not yet). The invite link appears once with a Copy button and the
     72-hour note; reloading the page must not show it again.
   - **Public address.** The current address as a full link (`APP_BASE_URL` host + `/<slug>`), or
     "Not set"; an input with the rule in a hint (2–40 lowercase letters, digits, hyphens; starts
     with a letter or digit); "Save public address". Domain errors (in use, not allowed) show next
     to the input.
   - **Status.** Active: a "Suspend organization" button that first reveals a confirmation stating
     the D-037 effects, with "Confirm suspend" and "Cancel". Suspended: "Restore organization",
     no confirmation needed.
   Each section shows its own success or error message; no generic "Organization updated."
4. An unknown or malformed id returns HTTP 404 (`notFound()`), the same as a non-admin gets for
   every `/admin` route. Look the organization up with `listOrganizationsForAdmin` and find it by
   id; do not add domain functions.
5. **Layout:** `src/app/admin/layout.tsx` gives all admin pages (including Site announcement) a
   header in the board's style with navigation: Organizations, Site announcement, and a link back
   to the board. If you build a shared admin header, put it in `src/components/board/admin-shell.tsx`
   and export it from `src/components/board/index.ts`.
6. **Server side unchanged in meaning:** every action still calls `requireAdmin()` first and the
   same domain function; the `forbidden_or_not_found` and `validation_failed` handling still holds.
   You may split `mutateOrganization` into one action per operation and return a `field` with
   errors.

## The trap

- **loading.tsx** (hazard 1e6662e8): do not add a `loading.tsx` under `src/app/admin/organizations/`
  or anywhere above it. It turns `notFound()` into a streamed 200. Test the 404 status of an
  unknown id and of the organization page for a non-admin.
- **The invite link is a secret shown once.** Never put it in a URL, a redirect, a log line, or
  anything that survives a reload. Keep it in the action's return value only, as today.
- **Admins who own no organization.** A site admin may have no org (they land on
  `/no-organization`). Admin pages must not call owner-only domain functions or `ownerPrincipal()`.
- **Existing admin tests.** The three e2e files listed under "Read first" use today's labels and the
  `listitem` card layout. Update their locators to the new pages. Keep every assertion's meaning:
  create, set owner, suspend, restore, invite link shown once and claimable, public address saved,
  non-admin 404. Declare each change in EXISTING CHECKS MODIFIED.
