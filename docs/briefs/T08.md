## What must be true when you are done

**Every page and server action**: call `requireHuman()`, route with `humanLanding`, and pass the
principal to the domain. Never take an org id, user id, or author from a form field or query
string. Map `DomainError` codes to plain messages; `forbidden_or_not_found` renders a 404.
Never show a raw driver error. Each page has explicit empty, loading, and error states. Controls
are keyboard-operable with visible labels. Markdown goes through the shared component only.
Retries and double submits (D-027): every submit control is disabled while its request is
pending. Where the domain operation accepts an idempotency key (`createProject`, `postRoot`,
`postReply`, `updateRootFlags`), generate it when the form renders and reuse it on resubmit. The
other mutations take no key, and none is to be added:
- set-style operations (update, archive, restore, grants, defaults, revoke) repeat harmlessly;
  a repeated archive may log a second audit row and event, which is acceptable;
- announcement set/clear use `expectedVersion`: a retry after a commit returns `version_conflict`,
  so reload and show the current state, which already contains the user's change;
- `createToken` and `replaceToken` have no key: a double submit can issue two tokens. That is an
  accepted residual risk because both are listed and revocable.

## The trap

The shell makes it easy to render something from the wrong context. Three failure modes, each a
cross-tenant or stale-data leak:
- Reading counts or announcements outside `withOrgTx`.
- Caching a server component's data across users (`unstable_cache`, `fetch` caching, a
  module-level memo).
- Showing a project count that includes archived projects or other orgs.

Every page here is per-user and per-request. Do not add any cross-request cache. An e2e test must
sign in as two owners of different orgs in turn and show neither sees the other's projects,
counts, announcement, or audit rows.
