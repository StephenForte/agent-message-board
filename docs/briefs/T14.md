## What must be true when you are done

Each item is a property with at least one test. Where an existing test already proves it, cite it
in the matrix instead of duplicating it.

1. **Restricted-token isolation (§15.4)**, through the MCP route: a restricted token cannot list,
   search, read, check, post, reply or update a project outside its allowlist by guessed project
   id, thread id or message id. Every denial is `forbidden_or_not_found` with the same message and
   details as a random uuid, so existence is not disclosed. Search returns no title, snippet or
   count from a hidden project. Broad tokens see a project created after the token. Default
   assignments to a hidden project never widen access.
2. **Cursor and continuation abuse (§15.4, §15.10):** a cursor or continuation issued to token A
   and replayed by token B (same org, narrower scope), by a token in another org, after a grant is
   removed, or with one byte changed, gives `invalid_cursor` with the resync instruction and leaks
   no event from a hidden project.
3. **Next-request revocation (§15.8):** revoke, expire, remove a grant, and suspend the org, each
   between two calls on the same session id. The second call is denied (401 for revoked/expired,
   `org_suspended`, `forbidden_or_not_found` for the removed grant), with no stale principal.
4. **Error hygiene (from the T11 review):** MCP error responses from non-domain failures never
   contain internal text. Inject failures inside a tool (a domain function that throws an `Error`
   carrying a marker string, a SQL-looking message and a stack) and at the HTTP layer (malformed
   JSON, wrong content type, a JSON-RPC batch, GET and DELETE, a body just over 64 KiB). Assert on
   the raw HTTP response text, not only the parsed result: no marker, no "at " stack frame, no
   "relation", "syntax error", "pg", or file path. T11's test checks logs, not responses; a
   planner probe showed the code is correct today, so this is a guard, and its negative control
   (below) is what proves it.
5. **Secrets and logs (§14, D-009):** across a run of every MCP tool and the web token pages, no
   log line contains an `amb_` secret, an Authorization header value, a message body or a title.
   Capture logs the way existing tests do.
6. **Cross-adapter injection (§15.12):** a hostile Markdown body posted through MCP (script tags,
   `javascript:` and `data:` links, raw HTML, an `onerror` image) renders inert on the website
   board and thread pages (e2e; assert no dialog fires and no such attribute is in the DOM).
7. **Browser CSRF (§14, D-003):** a server-action POST with a foreign `Origin` header is rejected
   by the production server and changes nothing (e2e or a raw fetch against port 3100).
8. **Human boundaries (§4, §15.1):** owner A cannot read owner B's project, thread, token or agent
   pages by guessed slug or id (404, the same as a random id). A site admin who is not an owner
   gets no board content of any org through any domain read. A verified user with no organization
   reaches no content. An owner cannot reach `/admin`.
9. **RLS catalog guard (D-020):** a test that reads `pg_class`/`pg_policies` and asserts every
   table with an `org_id` column has RLS enabled and forced and at least one policy, so a future
   migration that forgets one fails. Include the D-020 bypass control (a BYPASSRLS role does see
   other orgs' rows) so the test cannot pass vacuously.
10. **Rate limits are per token (D-029):** token A at its write limit does not throttle token B in
    the same org.
11. **Capability matrix (§13, §15.15):** `docs/capability-matrix.md` is a table. Rows are
    operations: every MCP tool; human-only operations (token create/revoke/replace/grants, agent
    defaults, announcements, project archive/restore, org provisioning/suspension); and operations
    agents must not have (create organization, issue credentials, edit announcements, archive a
    project, choose a human author). Columns: owner (browser), site admin not owner (browser),
    verified user without org (browser), org-wide token (MCP), restricted token (MCP), revoked or
    expired token (MCP). Each cell is allowed or denied plus the test that proves it, as
    `path › test title`. Also assert MCP `tools/list` returns exactly the nine T11 tools, so a new
    tool cannot appear unlisted. A unit test under tests/unit/security/ parses the table and
    fails if any referenced file is missing or does not contain the cited title.

## The trap

Isolation tests pass vacuously in three ways, and each has bitten this project or one like it:
running as a superuser, which skips RLS (D-020); asserting "denied" for an id that does not exist
anywhere, so the test cannot tell "hidden" from "absent"; and checking a parsed result while the
leak is in another field or in the raw body. The consequence is a green security suite that would
stay green with the protection removed, which is worse than no suite because it is cited as
evidence at the launch gate.

So every denial test uses a real object in another org or project. Every RLS test runs as the
non-superuser role. Every leak assertion reads the raw response. And you prove the suite bites:
for at least these four, temporarily break the product locally, show the named test goes red, then
restore. Do not commit the break. Report each one as "break → test → red" in VERIFICATION:
(a) `errorResult` passing a non-domain error's message through; (b) cursor verification skipping
the scope hash; (c) `assertProjectAccess` letting a restricted token through; (d) one tenant table
with FORCE ROW LEVEL SECURITY removed (in the test database only).

## When a test finds a defect

Do not fix product code. Commit the test marked as expected-to-fail (`test.fails` in Vitest,
`test.fail()` in Playwright) with a comment `DEFECT: <one line>`, so the gate stays green and the
test flips when the fix lands. Report it in DECISIONS NEEDED with the reproduction, and post it to
the board as a hazard. The planner dispatches the fix. If a defect makes the suite meaningless (for
example, isolation is broken across the board), stop and report instead.
