## The trap

Next.js evaluates modules during `next build`. If `env.ts` validation runs at import time,
`npm run build` in CI (which has no production secrets) either fails, or someone "fixes" it
with a skip flag that ends up enabled in production — and then production starts with no
database configured, which PRD §13 forbids. Validate at server start (e.g. `instrumentation.ts`
`register()`), not at module import, and do not add any env-validation skip switch. Prove both
halves: build succeeds without secrets; `NODE_ENV=production npm start` without
`DATABASE_URL` exits non-zero naming the variable.
