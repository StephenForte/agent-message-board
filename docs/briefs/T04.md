## What must be true when you are done

Modules `src/domain/projects/**` and `src/domain/credentials/**`, each with a README listing
its exports for wave 3/4. Use these exported names (argue in DECISIONS NEEDED if one is wrong;
do not silently rename). Every read that T07's briefing will compose also has an `…InTx(tx,
ctx, …)` form that runs inside a caller's `withOrgTx`; the plain form opens its own.

**Token authentication** (`credentials`):
- `authenticateBearer(authorizationHeader, { requestId, interface })` → `AgentPrincipal`
  (agentId and sessionId null) or throws `unauthenticated`. Parses `Bearer amb_<8>_<40>`
  (D-009), looks up by prefix through `withTokenLookupTx` only, compares SHA-256 hashes in
  constant time, rejects revoked and expired tokens, and fills `projectIds` from the token's
  current grants. An unknown prefix, a wrong secret, a malformed header, a revoked token, and
  an expired token are all the same `unauthenticated` to the caller. Updates `last_used_at`
  in an org-scoped transaction (the prefix path is SELECT-only by design and cannot write it).
  Hint: `withOrgTx` with a project-scoped principal whose `projectIds` is `[]` returns the
  token's current grants in `ctx.projectIds`.
- `connectAgent(principal, { name, clientLabel? })` → `{ agent, sessionId, capabilities,
  defaults, instructions? }`. Registers the org-local agent name if absent (D-014:
  case-insensitive unique, `^[A-Za-z0-9._-]{1,64}$`), reuses it otherwise, and creates an
  `agent_sessions` row bound to the token. `defaults` = the agent's `agent_project_defaults`
  intersected with what the token can access now, active projects only. Instructions text is
  T11's; return none or a placeholder field.
- `resolveAgentSession(principal, sessionId)` → the same principal with `agentId` and
  `sessionId` set, after `withOrgTx` verifies the session belongs to this token and org.
  Updates session and agent `last_seen_at`. A session of another token → `unauthenticated`.
- `selectSessionProjects(principal, projectIds)` writes `agent_session_projects`. Every id
  must be a current default and accessible, else `forbidden_or_not_found`.
- `resolveTargetProjects(principal, { projectId?, mode: 'read' | 'write' })` and its InTx form
  implement PRD §6: an explicit id is checked with `assertProjectAccess`; with no id, use the
  session's selected projects, else the agent's accessible active defaults. Write needs
  exactly one: several → `ambiguous_project` (list them in details), none →
  `no_project_selected`. Read may return several, each labeled with slug and name. Never
  guess a write destination.

**Owner-managed credentials** (human owner principal only; an agent principal gets
`capability_denied`; PRD §4: tokens never issue tokens):
- `createToken(principal, { label, scope: 'org' | 'projects', projectIds?, canCreateProjects?,
  expiresAt? })` → `{ token metadata, secret }`. The secret is returned exactly once and
  stored only as SHA-256 hex plus prefix. `canCreateProjects` defaults to true for `org`,
  false for `projects` (PRD §2).
- `listTokens`, `revokeToken`, `replaceToken` (creates a new token with the same label, scope,
  grants, and flags and returns its secret; the old one stays live until the owner revokes it,
  PRD §9), `setTokenGrants` (replaces the allowlist; emits `access.changed`).
- `listAgents` (name, last seen), `listAgentSessions` (token prefix, client label, created,
  last seen), `setAgentDefaults(principal, agentId, projectIds)`.

**Projects** (`projects`):
- `createProject(principal, { name, slug, description?, idempotencyKey })`. Owner: always.
  Agent: requires `canCreateProjects`, else `capability_denied`, and a resolved session (the
  schema needs `created_by_agent_id`). For a restricted token, in ONE transaction: the
  project, a `token_project_grants` row with `source = 'agent_create'` for this token only,
  an `agent_project_defaults` row for the creating agent, the `project.created` event, and the
  audit record (PRD §5, §10). Duplicate slug in the org → `validation_failed` naming the field.
- `updateProject` (name, description), `archiveProject`, `restoreProject`: owner only; agents
  get `capability_denied` (PRD §6). Each emits its `project.*` event and an audit record.
- `listProjects(principal, { includeArchived })` and `getProjectBySlug(principal, slug)`:
  only accessible projects; a slug the caller cannot access is `forbidden_or_not_found`.

Every mutation: one `withOrgTx`, the event(s) and audit in the same transaction, and
`withIdempotency` where the operation takes a key (at least `createProject`; `createToken`
and `connectAgent` do not need one). Audit before/after never contains a secret or hash
(the kernel rejects them; do not work around it).

## The trap

A restricted token's access must never grow except through the one documented path
(agent_create grants exactly the new project to exactly the creating token). Three ways it
silently grows: (1) treating defaults or session selections as permission. A default pointing
at a project whose grant was later removed must not appear in `connectAgent` defaults, must
not be selectable, and must not be resolved as a write target. (2) Granting the new project to
every restricted token, or to the agent rather than the token. (3) Reading the allowlist from
the principal built earlier in the request instead of `ctx.projectIds`, which `withOrgTx`
re-reads. Any of these lets a token see a project the owner never granted, and nothing in the
UI would show it.

Second trap: token secrets. Generate with `crypto.randomBytes` and rejection sampling into
base62 (no `% 62` modulo bias, no Math.random). The secret appears only in the create/replace
return value: not in audit, events, logs, errors, or test snapshots. The redacting logger
catches `amb_*` strings, but do not rely on it.

Third trap: concurrent first connections with the same new agent name (two clients started
together) must both end with the same agent id, not one `validation_failed` or a raw unique
violation. Use insert-on-conflict against the `lower(name)` index and then select.

## Coverage (properties; integration tests against real Postgres as the non-superuser role)

- Token auth: valid → principal with the org and current grants; wrong secret, unknown prefix,
  malformed header, revoked, expired → indistinguishable `unauthenticated`. After
  `revokeToken` or removing a grant, the very next call fails or loses the project, including
  with an existing session (PRD §15.8). `last_used_at` advances.
- The secret is not present in any table, audit row, event, or captured log line after create
  (search for it).
- Restricted-token `createProject`: project, grant (this token only), default, event, and
  audit all exist after success; inject a failure after the grant and none of them exist.
  Another restricted token in the same org cannot see the project. An org-wide token sees it
  with no grant. A restricted token without `canCreateProjects` → `capability_denied`.
- Two concurrent `createProject` with the same idempotency key → one project; same key with a
  different payload → `idempotency_conflict`.
- Defaults never widen: give an agent a default on project P, remove the token's grant on P;
  `connectAgent` omits P, `selectSessionProjects([P])` fails, `resolveTargetProjects` write
  with no id does not choose P.
- `resolveTargetProjects`: one default → it; two → `ambiguous_project` for write and both
  labeled for read; none → `no_project_selected`; explicit inaccessible id →
  `forbidden_or_not_found`.
- Concurrent `connectAgent` with the same new name (different case) → one agent id.
- `resolveAgentSession` with another token's session → `unauthenticated`.
- Agents calling owner-only operations (create/revoke tokens, grants, defaults, archive) →
  `capability_denied`, nothing written. Cross-org ids everywhere → `forbidden_or_not_found`.
- Archive/restore emit events in seq order and audit with before/after status.
