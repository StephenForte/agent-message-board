# T21 — Rate limits for anonymous public pages (D-036)

Public project pages (`/<org-slug>/<project-slug>` and their threads, T20) are readable by anyone
without signing in, and nothing limits how often they can be fetched. Each fetch is database work.
Add two in-memory limits in `src/proxy.ts` that reject excess public requests with HTTP 429 before
any database work happens.

D-036 (verbatim summary): count every request whose path passes `publicRobotsTag` (includes 404s for
unknown orgs/projects; excludes `/_next/` and all signed-in routes). Two fixed one-minute windows:
60 requests per client address, and 600 for all public traffic together. Client address = the
`True-Client-IP` header if present, else the first entry of `X-Forwarded-For`, else the single key
`unknown`. In memory in the proxy, before any database work; no table, no migration (staging runs
one instance). The address map has a fixed size cap. Response: 429 with `Retry-After` (seconds to
the end of the window), `Cache-Control: no-store`, `X-Robots-Tag: noindex`, and a short plain page.
At most one log line per minute per limit, counts only; client addresses never logged.

## What must be true when you are done

1. A new module `src/lib/public-rate-limit.ts` holds the limiter as plain code with no Next.js or
   database imports: a factory that takes `{ perAddress, global, maxAddresses, windowMs, now }`
   (with `now` injectable for tests) and returns a check function `(address) =>
   { allowed: true } | { allowed: false, scope: 'address' | 'global', retryAfterSeconds }`.
   Export the D-036 defaults as named constants: 60, 600, a cap of 10,000 addresses, 60,000 ms.
2. Window rule: fixed windows aligned to `floor(now / windowMs)`. A new window resets both counts.
   `retryAfterSeconds` is at least 1 and never more than 60.
3. Order: a request rejected by the per-address limit does not consume global budget. A request
   rejected by the global limit does not consume that address's budget. (State which order you
   chose and test it; the requirement is that one noisy address cannot use up the global limit
   for everyone else by retrying after its own 429s.)
4. Address cap: when the map is full and a new address arrives, drop entries from past windows
   first; if it is still full, do not track the new address (it still counts toward the global
   limit). Memory never grows past the cap.
5. `src/proxy.ts`: when `publicRobotsTag(pathname)` is non-null, derive the address per D-036, run
   the check, and on rejection return the 429 response directly (no `NextResponse.next()`), still
   carrying `x-request-id`. Non-public paths are never counted and never rejected.
6. Header parsing: trim whitespace; take the first comma-separated entry of `X-Forwarded-For`;
   cap the key at 64 characters; an empty value falls through to the next source.
7. Logging: on the first rejection in a window for each scope, write one `warn` line through
   `createLogger(process.env.LOG_LEVEL ...)` with `operation: "public_rate_limit"`, `scope`, and
   the rejected count from the previous window if you track it. Never the address.
8. `docs/ops/rate-limits.md` (new, short): both limit sets in one table (agent limits from
   `src/domain/ratelimit`, public limits from D-036), the single-instance assumption, and what a
   429 on a public page means for an operator.

## The trap

- **Module state in the proxy.** The limiter must be one module-level instance that survives
  across requests in `npm start`. Prove it with the e2e test below against the production server;
  a unit test alone cannot show that Next keeps the proxy module alive between requests.
- **Shared e2e address.** Every e2e request comes from the same machine and carries no forwarding
  header, so they all share the key `unknown`. A test that spends 60 requests on `unknown` will
  make the other public tests fail when they run in parallel. Give the rate-limit e2e test its own
  random `True-Client-IP` value per test. Never exercise the global limit in e2e (600 requests would
  429 every parallel public test); cover it in unit tests with small injected limits.
- **loading.tsx** (hazard 1e6662e8): do not add any. A 429 must stay a 429, not a streamed 200.
- Do not touch `src/domain/ratelimit`, the database, or any migration.

## Coverage

Unit (`tests/unit/public/public-rate-limit.test.ts`), with an injected clock and small limits:
- the per-address limit allows N and rejects N+1 with scope `address`;
- the global limit rejects across many addresses with scope `global`;
- the order rule from requirement 3 (a rejected address does not drain global budget);
- the window resets at the boundary; `retryAfterSeconds` is within 1–60 and correct mid-window;
- the address cap: fill it, add one more, size stays at the cap; past-window entries are pruned first;
- header parsing: `True-Client-IP` wins; first `X-Forwarded-For` entry; whitespace and empty values;
  64-character cap; fallback `unknown`.
- path selection: `/supa/t16-smoke`, `/supa/t16-smoke/threads/x`, `/nope/missing` counted;
  `/projects/x`, `/_next/static/a.js`, `/api/mcp`, `/`, `/supa` not counted (via the proxy's own
  decision function, exported for the test).

E2E (`tests/e2e/public/rate-limit.spec.ts`), using Playwright's `request` fixture with a random
`True-Client-IP` per test:
- 60 GETs to an unknown public path (for example `/rl-<random>/missing`, which returns 404 without
  needing any data) are not 429; the 61st is 429 with `Retry-After` between 1 and 60,
  `Cache-Control: no-store`, `X-Robots-Tag: noindex`, and an `x-request-id`;
- a request with a different `True-Client-IP` right after is not 429;
- a signed-in route (for example `/sign-in`) with the exhausted address is not 429.
