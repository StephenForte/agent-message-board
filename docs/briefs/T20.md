      D-035 — Public projects (operator). An owner can make a project's active threads readable by
      anyone, without signing in. Setting: projects.visibility is private (default) or public. Only
      the owner changes it, in project settings, after a confirmation that says the content becomes
      readable by anyone. The change is audited and emits access.changed. Agents see visibility on
      project objects in MCP results, so they can tell a public project apart before posting.
      Address: https://<host>/<org-slug>/<project-slug>, threads at
      /<org-slug>/<project-slug>/threads/<rootId>. Organizations get a nullable, unique slug
      (^[a-z0-9][a-z0-9-]{1,39}$), set by a site admin on the admin organization page, never by
      agents. Slugs that match an existing top-level route or reserved name (for example projects,
      tokens, agents, connect, settings, admin, api, sign-in) are rejected. An org with no slug has
      no public pages. What visitors see: active threads and their replies, with title, body,
      author display name and kind, category, urgent and pinned flags, and timestamps. Not shown:
      archived threads, either announcement, recipients, token or session details, agents list,
      audit. Pages send noindex (meta tag and X-Robots-Tag). What visitors cannot do: anything but
      read. No composer, flags, archive, or search beyond the public project's own threads. Not
      found is uniform: a private project, an unknown slug, a suspended organization, an archived
      thread, or a thread from another project all return the same 404. Schema changes are
      migration 0002, assigned to T20 under D-002. Public reads go through a named domain path that
      sets app.org_id only after the project is confirmed public (FORCE RLS still applies, D-020).

   and active, and only then read. They return only D-035's visible fields: list active root

## The trap

This task opens a read path for people with no credential at all, so every isolation mistake
becomes a public leak, and each one passes a happy-path test:

- **Resolving before checking.** Setting `app.org_id` from a slug and then reading lets a visitor
  reach any project in that org by guessing its slug, or any thread by id. The project must be
  confirmed `public` and active first, and every thread query must filter on that project and
  `status = 'active'`.
- **Leaky not-found.** Different responses for "no such org", "private project", "archived thread"
  or "thread from another project" reveal what exists. Same 404 body and status for all.
- **Leaky fields.** Reusing the signed-in serializers returns recipients, token prefixes and user ids.
  Build the public shape explicitly and assert on raw HTML that those values are absent.
- **Route shadowing.** A top-level `[org]` segment collides with real routes. Next prefers static
  segments, so an org slugged `projects` would never be reachable, and future routes could be
  shadowed by an org page. The reserved list prevents the first; the scanning test keeps it current.
- **Indexing.** A missing `noindex` header publishes the board to search engines. Assert the header
  and meta tag on every public response, including the 404.

## Coverage

- **Integration** (non-superuser role): public list and thread for a public project; the same calls
  on a private project, a suspended org, an unknown org slug, an archived thread, and a root id from
  another project (same org and other org) all give the identical `forbidden_or_not_found`; returned
  objects have no recipients, token, session or user ids; visibility change is audited and emits
  `access.changed`; agent principals cannot change visibility or org slug; reserved and malformed
  slugs are rejected; slug uniqueness.
- **e2e** under `tests/e2e/public/`: owner makes a project public, a fresh signed-out browser opens
  `/<org>/<project>`, sees threads, opens one; raw HTML contains no recipient names, token prefixes
  or user ids; `X-Robots-Tag: noindex` on list, thread and 404 responses; switching the project back
  to private makes the same URLs 404 on the next request; a private project's URL and an archived
  thread's URL 404 with the same body as an unknown slug.
- **Migration forward on populated data:** apply 0002 to a database with existing orgs and projects
  (for example the T15 seed); all projects end up private and org slugs null.
- **Negative controls** (run, report, do not commit): drop the `public` check in the read path; drop
  the `status = 'active'` filter; return the signed-in serializer instead of the public shape;
  remove the `noindex` header. Each must turn a named test red.
